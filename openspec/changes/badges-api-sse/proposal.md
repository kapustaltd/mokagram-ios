## Why

Бэкенд галочек теперь отдаёт актуальный список и мгновенные изменения по HTTP (`https://api.moka.wtf/v1`), а Desktop уже перешёл на него (kapustaltd/mokagram `f8e4dc11`: список с API как главный путь, события по SSE, GitHub и `@mokagent` остались запасными). iOS всё ещё берёт список из `badges.json` на GitHub раз в минуту и ходит в `@mokagent` через инлайн-запросы, поэтому выдача и снятие галочки доходят с задержкой, а персональные значки и подписи, которые сервер уже умеет хранить, на iOS не видны вовсе.

## What Changes

- Главный источник списка галочек: `GET https://api.moka.wtf/v1/badges` (с `ETag`). Цепочка запасных путей остаётся: GitHub raw, затем инлайн-запросы `badges:N` к `@mokagent`.
- Живые обновления: поток `GET https://api.moka.wtf/v1/events` (SSE). События `granted` / `updated` / `revoked` применяются к одному пользователю без перезагрузки всего списка; видимые строки обновляются сразу.
- Переподключение с `Last-Event-ID`; при `hello.resync = true` список загружается заново.
- Личные данные галочки с сервера: `emojiId` (значок, `null` = значок по умолчанию), `signature` (подпись), `blue` (синяя галочка со своим значком `blueEmojiId`). Поле `tier` и `source` не используются.
- Кэш на устройстве переходит на формат, который хранит `rev`, значки и подписи отдельных пользователей; старый кэш читается и не теряется.
- Значок в шапке профиля (обязательная поверхность) и его обновление в уже открытом профиле; причина, по которой на устройстве его нет, выясняется первой задачей.
- Подпись галочки: роль команды, затем подпись с сервера, затем «Поддерживает mokaGram»; текст под блоком профиля.
- Разработчики определяются по id и по имени (`ecronx`, `xdshkaaa`, `xdshka`, `litteraliy`), синий значок разработчиков как на Desktop; серверный синий согласуется с ним приоритетом.
- Журнал работы с галочками (подключение, события, обрывы) для отладки по проводу.
- Поток живёт только на переднем плане: при уходе в фон закрывается, при возврате сначала обновляется список, потом поток открывается снова.

## Capabilities

### New Capabilities

- `badges-api`: откуда клиент берёт список галочек и их изменения (API, SSE, запасные источники), какие данные галочки он применяет и как ведёт себя при обрывах, фоне и офлайне.

### Modified Capabilities

None. (Требования `verification-badges` из незаархивированного изменения `verification-badges` не меняются: где и каким значком рисуется галочка, остаётся прежним. Добавляются только источник данных и личные значки.)

## Impact

`submodules/Moko/MokoCore/Sources/MokoBadges.swift` (разбор ответа API, события, кэш, личные значки), его тесты `MokoCore/Tests/MokoBadgesTests.swift`; `ApplicationContext.swift` и `AppDelegate.swift` (запуск и остановка потока по жизненному циклу приложения); `PeerUtils.swift` (`mokaBadgeIconFileId` читает личный значок); `PeerInfoHeaderNode`, `PeerInfoScreen`/`PeerInfoProfileItems` (значок, подпись, перерисовка по уведомлению); при необходимости `ChatControllerContentData`/`ChatUserInfoItem` (карточка «о чате»). Новое сетевое обращение к `api.moka.wtf` (https, ATS не мешает). Сервер и бот в этом репозитории не меняются.
